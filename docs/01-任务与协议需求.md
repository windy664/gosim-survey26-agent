# 01 · 任务与协议需求（participant-agent-protocol-v4）

来源：官方参赛指南（`kit/docs/participant-guide.zh.md`）+ 平台 /docs 页。数值以 `initialize` 实际下发为准。

## 1. 任务概述

智能体模拟操作一台光谱巡天望远镜，在给定观测周期（约一季、38 夜）内自主决策每次曝光的：

- **时刻**：模拟时间由动作推进（observe/wait 消耗模拟时间；report 不推进）
- **指向**：`pointing.alt_deg` ∈ [0, 90]，`pointing.az_deg` ∈ [0, 360)
- **时长**：`duration_seconds` 整数秒，闭区间 **[60, 3600]**（夜末截断可短于 60）
- **观测程序**：`DARK` / `BRIGHT` / `BACKUP`（省略按 BACKUP 处理，务必显式声明）
- **光纤指派**：`assignments` = `{光纤编号: target_id}`，**必须显式给出**，后端不自动指派；同一光纤/同一目标一次动作只出现一次

**评分硬条件**：目标必须落在所指派光纤的可指派方格内，且**整次曝光**高度角 ≥ `minimum_altitude_deg`（30°）。命中判定只在曝光起点进行（恒星跟踪假设）；未命中不扣分但时间不返还。

## 2. 通信与运行约束

| 项 | 要求 |
|---|---|
| 传输 | stdin/stdout，**JSON Lines**（每条消息独占一行） |
| stdout 纪律 | 只输出协议 JSON；日志一律写 stderr（违反 → `agent_error`） |
| 序列号 | 每条 `decision_response` 必须原样带回请求中的 `decision_sequence` |
| 响应大小 | 单条响应 ≤ `limits.response_max_bytes`（示例 524288 字节 = 512 KiB，按 UTF-8 计） |
| 墙钟时限 | `limits.global_wallclock_seconds`（**示例 900 秒**），从第一条 `decision_request` 起算，含思考与模型调用时间；**无单次决策独立时限** |
| 依赖安装 | 不计入 900 秒（讲座官方口径） |
| 结束 | 时限耗尽 → `global_wallclock_expired`；正常结束收到最终 `finish` 消息（`grace_seconds: 30` 用于收尾退出） |
| 提交物 | 公开 GitHub 仓库链接，或私有 ZIP（≤50MB；页面拖拽单次 ≤20MB/2000 文件）；项目根带 `observer.project.json` 清单 |

## 3. 消息流

```
后端 → initialize            （仅一次，无需回复）
后端 → decision_request seq=1 ┐
agent → decision_response 1   │  循环直到巡天结束 / 时限耗尽 / finish / agent_error
...                          ┘
后端 → finish                （无需回复，30s 宽限退出）
```

`termination_reason` ∈ `survey_complete` / `agent_finished` / `global_wallclock_expired` / `agent_error`。除 `agent_error` 前的非法动作外，已完成的有效观测与举报奖惩照常计分。

## 4. initialize.payload 字段（公开配置全集）

- `task_card`：`card_id`、`scenario_slug`、`phase`
- `site`：`latitude_deg`、`longitude_deg`（东经为正）、`utc_offset_hours`（**仅用于读时间，天球计算一律用 UTC**）、`sun_altitude_limit_deg`（−18）、`minimum_altitude_deg`（30）
- `survey`：`start_utc`、`end_utc`、`slot_seconds`（900）、`nights[]`（`night_id` / `night_date` / `observing_start_utc` / `observing_end_utc` / `slot_count`）
- `instrument`：`n_fibers`、`grid_side`、`fiber_area_deg2`、`gap_deg`、`glass_side_deg`、`pitch_deg`、`fov_side_deg`、`layout`、`exposure.{min,max}_duration_seconds`
- `scoring`：完整计分配置（见 02 文档附录 key 索引）
- `footprint[]`：`component_id` + `vertices`（赤经赤纬顶点，大圆弧连接）
- `targets`：`columns` 声明列序 + `rows`（`target_id` / `ra_deg` / `dec_deg` / `target_class` / `feature_flux` / `science_weight` / `required`）
- `limits`：`global_wallclock_seconds`、`max_consecutive_reports`（示例 32）、`response_max_bytes`、`decision_timeout`（当前仅全局）

## 5. decision_request.payload 字段

- `now_utc` / `survey_end_utc`：当前模拟时刻与周期结束时刻（UTC）
- `observe_action_index`：已执行曝光动作数
- `running_total`：各目标最佳得分之和（**不含** required 罚分/均匀度/请求/举报项）
- `wallclock`：`elapsed_seconds` / `remaining_seconds`（真实时间）
- `latest_bulletin` / `latest_forecast`：最新公告与预报
- `active_requests[]`：进行中限时观测请求及进度（`completed_target_ids` / `completed_count` / `remaining_count`）
- `new_messages[]`：自上次决策以来新送达的全部消息（公告/预报/请求/请求结算/举报结果/状态更正）
- `last_result`：上一动作结果；observe 时含 `assigned_count`、`hit_count`、`hits[]`（`target_id`+`score`，**不回传光纤编号**；得 0 分也算命中——可能是天气关闭）

## 6. 公告与预报的粒度

- **bulletin**：每 slot（900s，对齐 UTC 整 15 分）一条；`notices[]` 只含 `event_kind` + `direction`（8 扇区 / ALL）；`initial=true` 仅全场第一条（公布 `terrain_obstruction` 方向）。**notices 为空 ≠ 天气好**：背景关闭与仪器故障不公告。
- **forecast**：首夜起每 7 个日历日发布一次，覆盖 7 天；`notices[]` 含 `event_kind` + `direction` + `nights[]`（夜粒度）。进入预报的事件一定发生，不确定性只在粒度。
- `event_kind`：天气五类 `rain` / `storm`（可致关闭）、`overcast` / `haze`（降透过率/天光质量、增 seeing）、`cold_snap`（全场降质）；特殊 `rocket_launch`（隐藏方位扇区+高度上限，公告方向只是扇区中心的粗略映射）、`earthquake`（不预报，事后公告，仪器效率逐夜恢复）、`terrain_obstruction`（全程有效低空遮挡）。

## 7. 动作与错误终止

四类动作：`observe` / `wait`（`duration_seconds` 或 `until_utc`，二选一）/ `report` / `finish`。

以下情况 → `agent_error` 终止该卡：JSON 无法解析、超响应大小、协议版本或 `decision_sequence` 错误、未知或多余字段、超范围/非有限数值、非整数秒、未知目标、重复光纤或目标、连续 `report` 超 `max_consecutive_reports`（示例 32，第 33 次终止；wait/observe 重置连续计数）。

光纤编号按整数解释（`"5"` 与 `"05"` 同根）。天顶指向（alt=90）az 任填，但会影响网格方向，须按所填值计算指派。

## 8. Hard mode 事件（仅部分卡启用，见 03 文档）

- **`data_loss`**：作废一段连续 observe 动作（按动作索引比例区间 `[⌊iN⌋, ⌊jN⌋)`），通过 `state_resync` 消息送达：含 `invalidated_window`、仍然有效的 `observed_target_ids` + `best_scores`、重算后的 `observation_requests`。**作废的曝光时间不退还**。智能体须据此重建"已完成目标"账本；`running_total` 同步更正。若已结算请求被影响，会收到 `revised: true` 的结果。
- **`pointing_offset`**：从周期开始即对每次 observe 叠加固定隐藏指向偏差；无任何消息通知，只能从"反复指派却不命中"的反馈推断并自校准。

## 9. 智能体可见 / 不可见

| 可见（公开） | 不可见（隐藏） |
|---|---|
| 台址、目标目录、天区边界、仪器参数、完整 scoring 配置、观测夜历 | 逐 slot 天气真值（seeing/透过率/sky_quality/仪器效率数值） |
| 公告（slot 粒度，类别+方向）、预报（7 天，类别+方向+夜） | 事件精确起止时刻、空间边界、强度乘数 |
| 曝光反馈（命中目标+得分）、限时请求进度、举报结果 | 仪器故障存在与否（只能从得分异常推断）、天气生成随机种子、pointing_offset 数值 |
